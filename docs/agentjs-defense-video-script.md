- **目标时长**：8 分钟，允许成片误差不超过 5 秒。

### 5. 1:55-2:38｜设计贡献一：面向 Agent 负载的数据路径组合优化

**素材与镜头**

- 使用 PPT 第 13 页，裁去底部来源栏和页码。

**逐字口播**

> 第一项设计贡献，是针对 Agent 常见数据形态组织运行时数据路径。工具结果中经常同时出现普通字段、少量特殊属性、大索引、短命对象、ASCII 文本和重复脚本。我们组合使用分段稠密数组，避免大索引触发一次性扩容；用 Descriptor 旁路表保持普通元素访问紧凑；再配合非移动回收槽位复用、ASCII 快路径和 isolate 内有界脚本缓存，控制这些常用路径的时间与空间成本。这里的贡献是面向场景的组合设计与完整实现，不宣称提出了新的数组、回收或缓存算法。

**屏幕强调字**

`场景化组合优化，不等同于原创基础算法`

### 6. 2:38-3:25｜设计贡献二：按 action 隔离的资源预算与受控 Host

**素材与镜头**

- 使用 PPT 第 14 页，裁去底部来源栏和页码。
- 先强调 action 外框，再按“生命周期隔离 -> 分层预算 -> 最小 Host -> 结构化输出”依次点亮。
- 当讲到最小 Host 时，画面只列出允许能力，不使用带绝对安全含义的图标或文案。

**逐字口播**

> 第二项设计贡献，是把生命周期隔离、资源预算和 Host 能力组合成一次 action 的受控执行边界。无关 action 使用新的 isolate，避免全局变量和原型修改相互泄漏；循环、递归、虚拟机栈、堆、大对象和执行时间分别受限，越界时返回明确错误。默认 Host 只开放必要能力，不向脚本提供文件、网络、进程、DOM 或 Node API。结构化 RenderTree 还会检查类型、循环引用、深度和字节数。这个边界依靠能力最小化和运行时校验，而不是字符串黑名单；我们也不把它表述为能够覆盖所有威胁模型的形式化安全系统。

**屏幕强调字**

`Fresh isolate｜分层预算｜最小 Host｜结构化错误`
